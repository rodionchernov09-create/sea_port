# Моделирование работы морского порта

Консольный backend на C++20 моделирует работу порта в течение месяца: расписание и
фактические прибытия судов, сезонную погоду, динамические очереди, разгрузку тремя
типами кранов, уход судов, рейтинг, доходы и штрафы. Отдельный режим подбирает
экономически выгодное количество кранов с учётом их покупки.

## Сборка и запуск

Требуются CMake 3.20 или новее и компилятор с поддержкой C++20.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

Для короткой команды в терминале добавьте скрипт в `~/.local/bin` (каталог
должен быть в `PATH`):

```bash
ln -s "$(pwd)/scripts/Seaport" "$HOME/.local/bin/Seaport"
Seaport
```

`Seaport` при необходимости пересобирает GUI и открывает окно из папки проекта.
Чтобы открыть исходники проекта в Zed:

```bash
ln -s "$(pwd)/scripts/project_seaport" "$HOME/.local/bin/project_seaport"
project_seaport
```

Режимы запуска:

```bash
./build/sea_port                 # интерактивная настройка каждого дня
./build/sea_port --auto          # полностью случайный месяц
./build/sea_port --optimize      # экономический подбор количества кранов
./build/sea_port --auto --seed 7 # воспроизводимый сценарий
```

В интерактивном режиме сначала выбираются сезон, краны, вместимость ожидания,
разгрузочные места и шаг вывода. Для каждого дня можно выбрать погоду и добавить
ручные либо случайные заявки на срок до семи дней вперёд.

## Основные правила

- Сухогрузы перевозят зерно, танкеры — нефть, контейнеровозы — контейнеры.
- Каждому грузу соответствует собственный тип крана и очередь.
- Разгрузка начинается только при наличии крана и подходящего разгрузочного места.
- Погода изменяет дневную производительность кранов; волны уровня 5 останавливают их.
- Дорогие заявки имеют приоритет, но длительное ожидание и близкий уход повышают
  приоритет дешёвого судна и предотвращают его бесконечное вытеснение.
- За немедленное обслуживание начисляется 12% бонуса. Долгое ожидание уменьшает
  начисление вплоть до 55% базовой стоимости.
- За каждый день сверх плановой стоянки вычитается настраиваемый штраф.

Начальная стоимость кранов:

| Тип | Стоимость, у.е. |
|---|---:|
| Для сыпучих грузов | 600 000 |
| Для жидких грузов | 900 000 |
| Контейнерный | 1 200 000 |

Все значения находятся в `SimulationConfig` и могут быть изменены вызывающим кодом.

## Графический интерфейс

Интеграция интерфейса находится в истории ветки `frontend`; локальная `main`
обновлена до неё. Перед сборкой загрузите ImGui:

```bash
git submodule update --init --recursive
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel
ctest --test-dir build --output-on-failure
./build/sea_port_gui
```

Для GUI требуются OpenGL и GLFW 3 (пакет разработки).
Для сборки только консоли используйте `-DSEA_PORT_BUILD_GUI=OFF`.
План, результаты проверки интеграции и журнал изменений: `docs/WORK_LOG.md`.

### Визуальная симуляция порта

```bash
git submodule update --init --recursive
cmake -S . -B build-local -DCMAKE_BUILD_TYPE=Debug
cmake --build build-local --parallel
./build-local/sea_port_gui
```

Если системный GLFW отсутствует, CMake собирает зафиксированный `external/glfw`.
На Linux нужны заголовки OpenGL и библиотек оконной системы (X11/Wayland).

1. Задайте число кранов, причалов по трём типам грузов и мест ожидания.
2. При необходимости добавьте суда и погоду. `Generate random ship traffic`
   позволяет отключить случайные заявки и оставить только ручное расписание.
3. Нажмите `START SIMULATION`, затем `RUN`. `STOP` останавливает автоматический
   расчёт дней; уже начатые анимации завершаются. `STEP` рассчитывает 1–3 дня.
4. `Playback speed` меняет скорость от 0.25x до 8x; при 1x сутки проходят за
   четыре секунды. `FINISH SIMULATION` сразу рассчитывает остаток месяца.
5. `BACK TO SETTINGS` позволяет настроить и запустить новый сценарий.

На карте: синее море, серые корабли, жёлтые грейферные краны для сыпучего груза,
бирюзовые наливные устройства, фиолетовые контейнерные порталы. Прямоугольники
B1, B2… — места у причалов, зелёная лампа означает занятый кран. Полоска над
судном показывает долю выгруженного груза; задержка после выгрузки может
удерживать судно у причала даже при 100%. Наведите курсор на судно для подробностей.

Слева — стоянка ожидания, ниже карты — отдельные очереди по типам груза.
Порядок обслуживания определяется бэкендом по стоимости, ожиданию и срочности.
Карта закреплена сверху и автоматически вписывается в окно; настройки и отчёты
прокручиваются в оставшейся области.
Лишние краны остаются резервными, если причалов меньше, чем кранов.

Расчёт остаётся **посуточным**: движение между состояниями — визуальная
интерполяция, не физическая навигация. Судно, разгруженное за одни сутки,
показывается уходящим от своего причала. Отказы и уходы из очереди тоже отображаются.

Отчёты и события доступны в раскрываемой панели; итоговая статистика — после
завершения. Журнал сессий: `logs/runtime/simulation.log` (дописывается при каждом
запуске). Журналы проверок и снимок интерфейса: `logs/`.
Для автоматической проверки запуска и полного месяца: `SEA_PORT_SMOKE=1 ./build-local/sea_port_gui`.
